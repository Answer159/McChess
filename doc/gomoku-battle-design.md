# 《方块五子棋》(MCChess Gomoku Battle) 玩法策划案

> 版本：v1.0（2026-09-10）
> 状态：设计定稿，待实施

## 一句话概括

**采集 + 即时落子 + 道具博弈的实时五子棋**：棋子不是回合制摆放，而是像资源一样要在地图上"抢"，谁先连成五子谁赢——但对手的铁锹随时可能铲掉你的连子。

---

## 1. 核心循环

```
刷子区 --采集(1子)--> 满载? --> 跑棋盘 --> 落子 --> 空手 --> 再跑
                        |                        |
                        v                        v
                   被处决剑杀 --> 掉落 <-- 道具销毁/偷取/转化棋盘上的子(破坏无掉落)
```

- 棋子是**频繁往返的现金流**：刷在棋盘近区，量大、随手可得
- 道具是**孤注一掷的大额投资**：按品质分层刷在离棋盘越来越远的环形区域，跑一趟外环 = 离开战场 40~60 秒

## 2. 棋盘与胜负

| 项 | 规则 |
|---|---|
| 对战形式 | **PvPvP 乱斗**：每个玩家自成一方（2~4 人），不做队伍对抗；棋子归属在逻辑上按玩家区分（引擎棋子值），**棋子外观也按玩家上色**（1黑/2白/3蓝/4绿，见`StoneNormalNameByValue`；外观只是展示，判定仍以引擎棋子值为准）。StartLogic 设 `gameMaxPlayerNum=4`：超过 4 人卡在等待阶段不开局（`/say` 提示），人数回落才继续 |
| 棋盘尺寸 | **随人数扩容**（`BoardSize` 基础边长=9×9 为 2 人局，每多 1 名玩家宽高 +2：3 人 11×11、4 人 13×13，上限 `FFAMaxPlayers`=4 人）。开局按在线人数重算，人数变少时上一局更大的残盘会在新一局清理重铺 |
| 棋盘形状 | **每局随机**（`RandomizeBoard`，默认开）：中心不动，BoardSize 见方内随机缺格——中心 3×3（`BoardCenterKeepRadius`）永远完整，越靠边缘缺格概率越高（最外环 `BoardEdgeRemoveChance`=50%，向中心按环距幂次平滑衰减）。缺格没有基座方块、本局无法落子，但**可以用便携棋盘补铺**（被破盘镐拆掉的格子同理）；每局开始重新生成形状 |
| 落子方式 | 手持棋子对棋盘格右键落子，落子归属=落子玩家本人（引擎按玩家棋子值区分，同值才连成己方线） |
| 胜负判定 | 服务端在每次落子后做 4 方向五连判定，先连成 5 子（或以上）的**玩家**立刻获胜 |
| 棋盘保护 | 棋盘上的棋子**徒手不可破坏**，只能被专用道具影响；被道具破坏的棋子**一律销毁，不产生掉落**（磁铁吸取进背包属于道具本体效果，不算掉落） |
| 平局兜底 | 回合计时（默认 8 分钟）到点未分胜负 → **突然死亡**：接下来任意一方落子即直接获胜 |
| 新手保护 | 刚落下的棋子 3 秒内**免疫一切道具效果**，防止对手贴身蹲落子秒铲 |
| 扩展格 | **便携棋盘**道具右键与初始棋盘同平面（或低一层）的地面铺一格 1×1 棋盘格，与主盘互相连线、统一判五连；距主盘中心 48 格内、不可与本局存在的主盘格/已有扩展格重叠（主盘天然缺格可补铺）；回合重置时扩展格整体拆除（被基座覆盖的原地形不恢复，若该列恰为新一周目的主盘格则补回基座） |

**连线播报**（降低门槛）：某方形成活三/冲四时，棋盘上对应线段自动发光/粒子提示，防守 urgency 可视化。

## 3. 地图布局与资源体系

复用模板 `script_ResourcePoint`（配置驱动：area / item / itemNumber / interval）。

```
+----------------------------------------------------------+
|                  [最外环 · 极低刷率]                       |

|     （可选：僵尸守卫，跑一趟 = 离开战场很久）               |
|                                                          |
|              +------------------------------+            |
|              |      [中环 · 低刷率]          |            |
|              |      破坏锹 / 处决剑           |            |
|              |   +------------------+       |            |
|              |   |   [内环 · 中刷率]  |       |            |
|              |   |   采集锹           |       |            |
|              |   |  +------------+  |       |            |
|              |   |  |  9×9 棋盘   |  |       |            |
|              |   |  | (边缘刷硬化  |  |       |            |
|              |   |  |  棋子)      |  |       |            |
|              |   |  +------------+  |       |            |
|              |   |  普通棋子矿        |       |            |
|              |   |  (黑白半区各一)    |       |            |
|              +------------------------------+            |
|                                                          |
|  [黑方出生点]                            [白方出生点]     |
+----------------------------------------------------------+
```

**距离即价格**：1+1 携带上限下，去外环意味着离开战场很久，对手在棋盘上白摆 1~2 子——捡到神器的代价就是对面的进度，滚雪球被自动抑制。

**棋子种类：**

| 棋子 | 采集方式 | 用途 |
|---|---|---|
| 普通棋子（石质） | **挖普通棋子矿**（须石镐级及以上） | 落子 |
| 硬化棋子（铁质） | **挖硬化棋子矿**（须铁镐级） | 落子（纯采集门槛，无落子特效） |
| 金矿（稀有） | 徒手速挖（镐也能挖，但方块不带 `netease:tier`，镐无加速系数），刷在**高级道具区间**（25~35 格，与处决剑同环） | 挖碎**直接得普通棋子**（不发金棋子）。定位：跑远环顺路白捡子的"惊喜"——免工具、挖得快，贴金只是外观区分。（金棋子/万能挡子机制已下线：曾为"落盘后阻断双方连线、永不获胜、只能雷管炸"的特殊子，简化后移除） |

**★棋子物品不直刷**：普通/硬化棋子**只能挖对应矿获得**（矿→棋子物品，见 `OrePieceItemDict`）——地上白捡的棋子会让镐子失去存在意义。方阵/陷阱棋子没有对应矿，仍走低频直刷。

**刷子节奏（初版参数，待平衡）：**

- 普通棋子矿：每半区约 4s/个（近环黑白半区各一片）
- 棋盘边缘也会随机冒出硬化棋子，逼人上前线采集
- 狂热时间：最后 90 秒全局刷子速度 ×2，制造必然的终局混战

**问号方块（随机道具块）：**

中环偏外（半径 18~28 格）独立刷新的特殊方块，生成逻辑自成一套（自己的半径/间隔 30s/场上上限 3 个，不占矿石与分级道具池的名额）。**任意镐可采**（石镐/铁镐皆可，不限定矿种；镐耐久 1 采一次即碎），徒手/没拿镐也能挖穿但拿不到奖励（与矿石"拿错工具白挖"同款体验）。采到后从独立奖励池 `RandomBlockPoolDict` 加权随机抽一个道具直接发到背包，并全服播报开出结果：

| 道具 | 权重 | 约出率 |
|---|---|---|
| 铁镐 | 20 | 17% |
| 转化墨水 | 20 | 17% |
| 爆炸雷管 | 20 | 17% |
| 便携棋盘 | 10 | 8.5% |
| 处决剑 | 10 | 8.5% |
| 破盘镐 | 10 | 8.5% |
| 加速药水 | 10 | 8.5% |
| 混乱药水 | 10 | 8.5% |
| 换位符 | 5 | 4.2% |
| 反伤药水 | 5 | 4.2% |
| 眩晕锤 | 5 | 4.2% |
| **笔刷** | **1** | **0.8%** |
| **吞噬黑洞** | **1** | **0.8%** |
| **时间停止** | **1** | **0.8%** |

权重是**相对值**（抽取时按合计 118 归一化，见 `DrawRandomBlockReward`），故常规道具统一放大到十位数——好让**笔刷/吞噬黑洞/时间停止**这种"极低概率"的彩票能用权重 1 表达出约 1% 的档位（开一百个问号方块才见一次）。**除石镐外全部道具都在池里**（分级刷新环照常另刷，问号箱是额外来源）；权重为占位默认值，按测试手感直接改 `RandomBlockPoolDict` 的数字即可，某件不想要就写 0。笔刷**刻意只有这一条获取途径**：不进 `ItemTierDict` 的任何环形刷新池，地上永远不会自然刷出（黑洞/时停同理，只走问号方块）。

奖励池刻意**不含棋子**——避开棋子携带上限（MaxCarriedPieces）满时抽到棋子无处安放的边界。设计定位：中环偏外的"赌点"，跑一趟有保底（镐类权重最高）也有暴击（处决剑/便携棋盘），最上面还压着约百分之一的**笔刷**（直接白送一局胜场），与金矿的确定性稀有形成对照。


## 4. 道具体系（7 件定稿）

| 道具 | 次数/耐久 | 效果 | 刷新位置 |
|---|---|---|---|
| 采集锹 | 耐久 12 | 采硬化棋子（采普通棋子也更快） | 内环（中刷率） |
| 破坏锹 | 3 次 | 铲掉棋盘上**任意他人**一枚棋子，销毁无掉落 | 中环 |
| 处决剑 | 一次性 | 一击击杀玩家，受害者掉落全部携带 | 中环 |
| 转化墨水 | 一次性 | 点击棋盘上**他人**一枚棋子 → **变成己方**（乱斗下归属转为使用者，按引擎棋子值判定） | 最外环 |
| 守护蜡 | 一次性 | 给己方一枚已落棋子上蜡 → **永久免疫所有道具效果**（铲不掉、炸不毁、吸不走、转化不了） | 最外环 |
| 板砖雷管 | 一次性 | 炸棋盘 2×2 区域，区域内棋子全部销毁（无掉落），坑 10 秒自愈 | 最外环 |
| 磁铁 | 一次性 | 吸对方一枚棋子进背包（变己方子）；背包已有棋子时使用失败且**不消耗** | 最外环（极低权重） |
| 反伤药水 | 一次性 | 右键激活护盾：下次受到**来自玩家**的伤害（攻击或玩家道具）时不落在自己身上，**全额反弹给伤害来源**（击杀归属记在护盾主人名下）；坠落等自然伤害/中立来源（箭矢、非玩家实体）不触发反弹、护盾保留；触发或新一局开始时失效 | 高级环（与处决剑/换位符同池） |
| 换位符 | 一次性 | 右键与**随机一名其他玩家**互换位置（2 人时即唯一对手；多人时随机抽，双方坐标先读后写，任一侧传送失败则回滚且不消耗） | 高级环（与处决剑/反伤药水同池） |
| 加速药水 | 一次性 | 右键饮用：移动速度提升 `SpeedPotionPercent`%（默认25%），持续 `SpeedPotionDuration` 秒（默认10s）后自动恢复；连喝不叠加只刷新时间；新一局开始清除 | 中环（与墨水/雷管/便携棋盘同池） |
| 眩晕锤 | 一次性（锤中即碎） | 锤中敌方玩家：**不造成伤害**，对方被眩晕 `DizzyHammerStunSeconds` 秒（默认1.5s，移速锁死+反胃画面+拳头无力）、**携带的道具全部掉落在地**且眩晕期间无法拾取（等对手来抢） | 高级环（与处决剑/换位符/反伤药水同池） |
| 混乱药水 | 一次性（砸中即碎） | 砸中敌方玩家：**不造成伤害**，对方混乱 `ChaosPotionConfuseSeconds` 秒（默认10s）——**前后左右移动反向 + 视角左右反向**（上下不反）。客户端实现：视角=每帧镜像yaw；移动=真实输入取负后 `LockInputVector`（W↔S、A↔D对调），输入来源按平台分层——PC键盘走 `OnKeyPressInGame` 按键事件、手柄走摇杆事件（事件驱动，键一变才锁）；**手机/触屏模式自造假摇杆HUD**（`chaosJoystickUI`）：`HideMoveGui` 隐藏原生左下移动按钮（原位置点击不再响应，让位）、isSwallow按钮自收触摸、固定底盘按原版尺寸出现在左下（拖动向量=触点-底盘中心）、输入向量自算自锁，摇杆头显示镜像位置；拖动位置来源双通道——真触屏走TouchMove回调、F11鼠标模拟走 `GetTouchPos` 逐帧轮询，抬手由 `TapOrHoldReleaseClientEvent` 判定。全屏表现用原版反胃（天旋地转、零伤害）。试败记录：负移速被引擎钳成0、客户端 `PosComponent` 无 `SetPos`、`GetInputVector` 锁定中只返回回声、逐帧解锁/重锁会抖动或定住、中毒伤害不触发 DamageEvent 且 `ActorHurtServerEvent` 的 damage 不可修改 | 中环（与墨水/雷管/破盘镐/便携棋盘/加速药水同池） |
| 笔刷 | 一次性 | 走到**比分记分牌**（编辑器 TextAnchor 预设位置 `ScoreBoardAnchor`）`BrushUseRadius` 格内右键（对空气也可以）：直接给自己的**系列赛胜场 +`BrushWinBonus`**（默认 +1，等于白捡一局），用一次即碎；离记分牌太远只提示、**不消耗**（"必须当众走到记分牌前"就是这件道具的全部成本）；记分牌关闭（`ScoreBoardAnchor=None`）时直接失效 | **不刷新**——唯一途径是问号方块，权重 1（≈0.9%） |
| 便携棋盘 | 耐久 2（可铺 2 格） | 右键棋盘平面或低一层的地面铺一格 1×1 **扩展格**（距主盘 48 格内、不与主盘本局真实存在的格子/已有扩展格重叠、需已分配本局棋子值；**主盘随机缺格与被破盘镐拆掉的格子可以补铺**；按住右键连发使用事件，`boardPlaceUseTime` 1秒去重防刷屏）；扩展格与主盘互相连线统一判五连，全部格子下满才平局 | 中环（与墨水/雷管同池）+问号方块奖励池 |
| 吞噬黑洞 | 一次性（释放即碎） | 右键释放：**吞噬棋盘上全部棋子**（不分归属；主盘+扩展格都清），基座与扩展格无损、清完仍可落子；引擎整盘重置，陷阱一并作废；空盘释放同样消耗（与雷管"炸了个空"同款语义）。双刃剑——己方快连五时用等于自爆，定位为劣势翻盘/终局搅局 | **仅问号方块奖励池**（权重1，与处决剑并列最稀有档，不入常规刷新环） |
| 时间停止 | 一次性（用一次即碎） | 右键使用（UseOn/TryUse双入口）：**除使用者外的全场玩家**冻结 `TimestopFreezeSeconds` 秒（默认5s）。双层实现：客户端关移动/跳跃/攻击输入（`operationComp` 的 `SetCanMove`/`SetCanJump`/`SetCanAttack`，视角转动保留、PC/触屏通吃），服务端登记到期时刻并拦截挖掘/落子/道具/攻击/拾取（`IsTimestopFrozen`）；冻结不锁血——冻结中的玩家照样可以被处决。新一局开始全体解冻，效果不跨局 | **仅问号方块奖励池**（权重1，与黑洞/处决剑并列最稀有档，不入常规刷新环） |

**设计说明：**

- **转化墨水 > 磁铁 > 破坏锹** 三档收益递减：墨水是"拆对面 + 白得一颗场上子"（可能直接接上自己的线），磁铁是"拆对面 + 背包得子（还要跑一趟才落盘）"，破坏锹是"只拆"。刷率与价值严格反向。
- **守护蜡是转化线的镜像**：唯一防守道具，专门保即将成五的线——让对手必须先解决蜡、再处理你的线，把终局博弈拉长一层。
- **处决剑的天然约束**：剑是一次性的，杀人收益是掉落物，但 1+1 满载时没空间捡等于白杀——剑要求"空手出剑"，本身就是一个微操决策点，无需额外设计。
- **雷管 vs 蜡**：雷管对上蜡的子所在格照样炸坑，蜡子留在原位悬空（行为 = 棋盘缺一格但子还在），**不影响五连判定**。
- 墨水对上蜡的子无效。

## 5. 携带限制与节奏控制（防"攒5子一波流"）

核心思路：**每一颗子都是一次远征**，靠背包容量控节奏，不做落子冷却。

| 限制 | 规则 |
|---|---|
| 携带上限 | **棋子 1 + 道具 1**；满载时无法再采集，采集失败给明确提示 |
| 落子冷却 | 初版**不做**，节奏全靠容量控制 |
| 背包掉落 | 被击杀时身上棋子和道具**全部掉落**，谁都能捡 |
| 满载提示 | action bar 常驻显示占用状态（棋子 0/1、道具 0/1） |

**节奏估算**：赢一局最少 5 次资源远征（还得对手不堵）。9×9 + 资源区距棋盘 15~20 格，纯物流约 3~4 分钟，加上攻防和道具，**单局 5~8 分钟**。测试偏拖时优先调"资源区间隔"，不要加上限。

## 6. 死亡与复活

| 项 | 规则 |
|---|---|
| 复活 | **无限复活**：死亡不弹原版界面（`immediate_respawn` 游戏规则），自动重生无需点击。引擎复活点由脚本设到棋盘外沿（`RespawnPosOffset`，常驻加载区内）——世界出生点在未加载区块，重生会卡死 |
| 血量 | **每局开始全体回满**（`OnRoundStart` 按各自 `GetAttrMaxValue(HEALTH)` 设回，只改当前值不动默认值）：上一局踩雷/互殴挂的彩不带到下一局 |
| 饥饿 | **整场屏蔽**（`script_World` 进图时 `SetDisableHunger`，客户端 `HideHungerGui` 把 HUD 鸡腿条也收掉；开关在 `worldConfig.disableHunger/hideHungerGui`）：本图节奏快，不做食物管理 |
| 冷却 | 重生后行动封锁 `DeathRespawnHoldSeconds` 秒（可配置，默认 5）：每秒聊天框倒计时，期间免疫伤害、拦截落子/挖掘/拾取/攻击，时间到自动恢复 |
| 掉落 | 死亡时身上棋子/道具全部掉落，无死亡惩罚（掉落本身就是惩罚；冷却期间连自己尸体上的掉落都捡不回来） |
| PvP | 击杀是控资源的合法手段：杀一个满载玩家 = 抢一颗子 + 抢一个道具 |

## 7. 队伍与结算

- **乱斗（PvPvP）**：不做队伍对抗，每人自成一方（棋子归属=落子玩家，`script_Gomoku` 开局按人头分配逻辑棋子值）；`script_Team` 的队伍仅保留出生点/传送/计分板等基础设施，队友间伤害已打开（`canHurtTeammate=True`）——乱斗下所有人互相均可造成伤害
- 五连即胜（按玩家记，先连成者本人获胜）→ 走 `script_EndLogic` 结算（胜者以玩家身份反查所在队伍记系列赛胜场）
- 突然死亡规则兜底（见第 2 节）

## 8. UI 与反馈

| 位置 | 内容 |
|---|---|
| action bar | 常驻：`棋子 1/1 | 道具 0/1`；采集失败时显示原因（"背包已满"） |
| boss bar | 回合计时（8 分钟倒计时） |
| 棋盘特效 | 落子粒子、活三/冲四线段发光、被铲/被吸走的棋子音效+粒子提示 |
| 计分板 | 右侧队伍栏（`script_Team` 的 teamUI）：**"队名"一栏显示该队参赛玩家的名字**（服务端 `GetQueuePlayerNameList` 随 `UpdateScoreboard` 推送，一队多人用"、"连接；不再显示"森林之子/火焰使者"模板队名），颜色仍按队伍色 |
| 比分文字板 | 立在编辑器 **TextAnchor** 预设位置（`config.ScoreBoardAnchor`）的世界文字板：一名玩家一行 `名字(色名)  胜场`，**该行文字用这名玩家自己的颜色** |

**比分文字板（TextAnchor）：**

- **统计口径 = 系列赛胜场（跨局累计）**：每局连成五子的玩家 +1，新一局开始**不清零**（服务端 `playerWinCountDict`，`OnRoundStart` 刻意不清空）。重连会换新 `playerId`，等于从 0 重记——与"棋子值不回收"是同一套取舍。
- **玩家颜色表**：`config.PlayerColorDict` 按**本局逻辑棋子值**（1~`FFAMaxPlayers`，开局按人头分配）给每人一色，每条带 `name` 中文色名 / `code` 聊天框 `§` 码 / `rgba` 文字板颜色。色名与棋石颜色一一对应（黑白蓝绿），与 `StoneNormalNameByValue` 保持同步。
- **为什么一行一块板**：引擎里一块 TextBoard 只有一个文字颜色，而需求是"每个玩家的分数用自己的颜色"，故拆成标题一块 + 每名玩家一块，自上而下按 `ScoreBoardLineHeight` 递减 Y 摆放。文字板是否支持 `§` 码未验证，故行文字不写 `§`，颜色统一走 `SetBoardTextColor`。
- **端侧分工**：TextBoard 是**纯客户端组件**（服务端无此 API），所以 GomokuMod 为此新增了客户端系统 `gomokuClientSystem`。服务端只算数与排版，把 `[[整行文字, RGBA], ...]` 经 `GomokuScoreBoardEvent` 推给客户端；客户端只做建板/改字/改色/回收（行数不变时只 `SetText`+改色，不重建板，避免每次结算闪一下）。
- **刷新时机**：开局（换颜色）/ 结算（记胜场）/ 玩家进退场各广播一次；新玩家进场时服务端延迟 1 秒补推一次，客户端建好板后也会主动发 `GomokuScoreRequestEvent` 索要——两条路各兜一半，晚进服/重连的人不必等到下一局结算才看到比分。
- **能被笔刷改写**：`笔刷` 道具（只从问号方块极低概率开出，见第 3、4 节）在记分牌 `BrushUseRadius` 格内右键即给使用者 `+BrushWinBonus` 胜场，走的是同一个 `playerWinCountDict`，成功后立刻 `BroadcastScoreBoard()`，文字板当场跳数。
- **整列抬高 + 始终面向镜头**：锚点方块是贴着地面放的（编辑器里点地表放预设），标题直接用锚点高度会把半截字埋进土里、玩家行更是在地下——整列抬高 `ScoreBoardLiftY`（默认 3 格：标题=锚点Y+3，玩家行向下排）。两块牌（本牌与 EndLogic 系列赛牌）都 `faceCamera=True`：固定朝向的板从背面看是空白板，森林里绕到背面的概率不低。EndLogic 系列赛牌立在 Gomoku 标题正上方 1.2 格（69.2），锚点挪动/抬高改动时两处 config 要同步改。
- **位置来源**：与 `BoardCenter` 同理**硬编码在 config**——不能在运行时读 `db/presets.json`，加载世界后引擎会把 virtual 预设消耗掉并清空该文件（已实测）。编辑器里移动 TextAnchor 后需把新坐标同步到 `ScoreBoardAnchor`；置 `None` 即关闭该功能。`ScoreBoardScale` 调大后 `ScoreBoardLineHeight` 要跟着加，否则上下行会叠在一起（只能进游戏肉眼调）。

## 11. 玩法模式（模式切换框架）

一局用哪套玩法由 **`config.GameMode`** 一个字符串决定，默认 **`"random"`**：**每局开局从注册表独立随机抽一个模式**（两局连出同模式属正常随机），切完 `/say` 全服播报本局是哪个模式。固定 `"classic"`（经典模式 = 原来的玩法）或 `"trap"`（整局固定陷阱模式）也行；写成没注册过的名字会记一条警告并自动退回 `"classic"`，不会开不了局。**固定模式改完要重进地图才生效**；`"random"` 的抽取每局开局重掷（等待阶段先用经典模式顶着，进图传送/复活点等钩子不查到未布好的陷阱模式）。

**目录结构（`script_Gomoku/gameModes/`）：**

| 文件 | 职责 |
|---|---|
| `baseMode.py` | `GameModeBase`：全部钩子的定义 + 默认实现（默认实现 = 经典行为，所以新模式只重写自己关心的那几个） |
| `classicMode.py` | 经典模式，除了打一行日志什么都不做（默认实现就是它要的行为） |
| `trapMode.py` | 陷阱模式的全部逻辑 |
| `trapModeConfig.py` | 陷阱模式**所有可调数值**（一个都没写死在 `trapMode.py` 里） |
| `modeFactory.py` | 工厂：`CreateGameMode(serverSystem)` 按 `config.GameMode` 造对象，未知键/构造异常都能兜底；`"random"` 键 + `PickRandomModeKey()` 供每局随机抽取 |

**钩子清单**（宿主 `gomokuServerSystem` 只认这些方法，不认识任何具体模式；模式之间互不 import）：

| 钩子 | 宿主调用点 | 用途 |
|---|---|---|
| `OnEnter()` / `OnExit()` | 系统构造 / `Destroy`；随机模式下**每局换模式时**也各调一次（`SwitchGameModeForRound`：旧模式 `OnExit` 收尾 -> 新模式 `OnEnter`） | 模式装载与卸载 |
| `OnRoundStart()` | `OnRoundStart` 里、**启动刷新协程之前**（随机模式的重掷/换对象也在这一步，`SwitchGameModeForRound`） | 本局场地准备（陷阱模式在这里撒生成点、长路径；地面原样不动） |
| `OnTick()` | `OnTickServer` | 每帧逻辑（陷阱模式的踩雷检查） |
| `OnPlayerAdd/Remove/Die(playerId)` | 对应的引擎事件处理里 | 玩家进退场与阵亡 |
| `OnPlayerRespawnFinish(playerId)` | 宿主的 `PlayerRespawnFinishServerEvent` 转发 | 玩家重生落地（陷阱模式把人从队伍复活点拉回安全圈） |
| `PickSpawnColumn(inner, outer, angleMin, angleMax)` | `SpawnAtRing` / `SpawnTierItem` / `SpawnRandomBlock` | **资源落点唯一入口**，返回 `(x, z)` 或 `None`（=本次刷新跳过）。默认实现就是原来那段"环上随机取点" |
| `CanPlaceBlock(entityId, x, y, z)` | `ServerEntityTryPlaceBlockEvent` + `HandleCellPlace` | 放置表决，返回 `False` 即取消（引擎事件里置 `args['cancel']=True`） |
| `GetRespawnPos()` | `GetEngineRespawnPos` | 模式自定义复活点；返回 `None` 走原来的棋盘外沿算法 |

三处刷新原本各自抄了一份"环上随机 + 夹半径"的代码，现在统一收进 `PickSpawnColumn`（经典模式里就是那段原逻辑），所以加模式不需要再动刷新代码。

## 12. 陷阱模式（`GameMode = "trap"`）

> 一句话：**地面完全不动（本图陷阱区地表就是基岩，挖不动也看不出区别），但只有"生成点 → 棋盘"的那几条路是安全的**，踩偏一格脚下就化成岩浆。

| 项 | 规则 |
|---|---|
| 安全区 | 棋盘外**两圈**（`SafeRingWidth`=2）永远安全，绝不会变陷阱；复活点也在这一圈上 |
| 陷阱区 | 以棋盘中心为心、半边长 `AreaRadius`=**15 格**的见方（切比雪夫环距），**地面一格方块都不动**——不整平、不铺伪装层（以前铺的草皮能被玩家挖穿打洞绕过雷区，已废弃）。哪些格是陷阱只存在脚本数据里，每局重掷；一切高度判定（踩雷高度带/岩浆摆放/弹回落点）按列查地表（宿主 `FindSurfaceY`，`GetTopBlockHeight` 含树叶） |
| 道具生成点 | 随机 `SpawnPointCount`=10 个，落在 `SpawnPointRadiusRange`=(13,15) 环距带里、互相至少隔 `SpawnPointMinGap`=3 格（该带约336格、间距3上限约13个，三个参数要一起算账）。**生成点不做任何标记**——场上除玩法道具（矿石/棋子/物品/问号方块）外一律不放其他方块（原版荧石路标已撤：非游戏方块出现在地图上会让人误以为是道具），玩家靠路径上刷出的资源认路 |
| 路径 | 每个生成点向安全区边界长一条格路：单调朝目标走（必然收敛）+ 粘着上一步的轴（`PathTurnChance`=0.35 才换轴），所以是几段直线拼的折线而不是锯齿；`PathWidth` 可加宽（有效宽度只能是奇数） |
| 安全格 / 陷阱格 | **先长路，剩下的全是陷阱**——顺序刻意如此：哪些格是安全的由路径唯一决定，资源刷新只要在安全格里取点就绝不会刷到陷阱上 |
| 踩雷 | 脚下那格是陷阱格 → 该列地表方块临时换成 `LavaBlockName`、掉 `StepDamage`=4 点血（`cause='lava'`，**来源不是玩家所以反伤药水不反弹**——踩雷是自己的锅）、被弹回**上一次站稳的安全格**（没站过就回安全区）；提示按 `TipCooldownSeconds` 节流 |
| 岩浆持久 | `LavaRestoreSeconds`=**3 秒**后复原成**触发前记下的原方块**（触发时先查该格方块名，查询失败退 `RestoreFallbackBlockName`=基岩）——**这格仍然是陷阱**，只是又看不出来了，下一个人照样踩 |
| 跳跃 | 只判定站在该列地表上的人（`abs(y-surfaceY) <= TriggerMaxHeight`=1.6，高于原版跳跃峰值约 1.25），所以蹦跳、疾跑跳都躲不过雷区。想允许"跳过一格陷阱"就把这个值调小 |
| 建造限制 | **陷阱格所在的整条竖列**禁止放任何方块（不限高度）——否则搭一条方块桥就能无视整片雷区。便携棋盘走的是道具逻辑、不过引擎放置事件，所以 `HandleCellPlace` 里补了一次同样的表决 |
| 资源刷新 | 只在**安全格（=路径格）**上刷，且要求该列地表**实心可站**（`SpawnRequireSolidGround`：树叶/树干/水面不算——宿主 `FindSurfaceY` 含树叶，不过滤矿石和道具会刷在树冠顶上够不着；过滤按格缓存，正冒岩浆的列也被顺带滤掉）；**安全区一律不刷**（需求明确："棋盘安全区不要生成任何棋子和道具"）。主 config 的环半径（最远 35 格）按 `SpawnRadiusSourceRange` 比例**重映射**进 `[安全圈外沿+1, AreaRadius]`，`RemapSpawnRadius=False` 则改为直接夹住——不重映射会让中环和外环全挤在最外圈，"距离即价格"的层次就没了。`angleRange`（黑白半区那套切法）照旧生效 |
| 死亡复活 | `GetRespawnPos()` 把引擎复活点压到安全圈上；重生落地（`PlayerRespawnFinishServerEvent`）后延迟 `RespawnFinishTeleportFrames` 帧把人拉回安全圈——LimitedRespawn 会在重生落地时把人传到队伍复活点（经典模式的复活位置，离棋盘很远），跨mod监听顺序不保证谁先被调，晚它几帧稳定压过（失败隔 `RespawnTeleportRetryFrames` 帧重试一次）；阵亡时清掉"上一个安全格"，免得复活后第一次踩雷被弹回死亡现场。重开一局/退出模式前会显式把还亮着的岩浆复原掉（不再整平重铺，残留岩浆必须收回） |
| 进场/开局落位 | 世界出生点在远处未加载区块：进图后延迟 `JoinTeleportDelayFrames` 帧查一次位置，离棋盘超过 `JoinTeleportRing`=50 格（切比雪夫）就把人拉进安全圈（等待区约35格、队伍落点16~31格，都在阈值内不会被误拉，StartLogic 的 lobby 流程不受影响）；开局时 StartLogic 先把玩家传到队伍落点，`RoundStartTeleportDelayFrames`=45 帧后陷阱模式再把全体拉进安全圈——开局就站在棋盘边上而不是隔着整片雷区。落位点=安全圈外沿随机一格（每人分开站），并记入"最近安全格" |

**为什么不用"先随机陷阱、再挖路"**：那样要反复检查连通性，还可能把资源刷在孤岛上。先路后陷阱是一次成型、零重试的写法——生成点挑选、路径行走、取点全部有步数/候选上限，开局不会卡住主线程。

**调参入口全部在 `gameModes/trapModeConfig.py`**：区域大小、安全圈、岩浆/复原方块名、生成点数量与间距、路宽与拐弯率、岩浆复原秒数、踩雷伤害、触发高度、检查频率、提示节流、复活延迟、进图/开局落位传送、刷新落点实心过滤。`trapMode.py` 里没有任何写死的可调数值。

## 13. 已拍板决策记录

1. 棋盘尺寸可配置，默认 9×9
2. 棋盘棋子徒手不可破坏，只能被专用道具影响；破坏一律无掉落
3. 硬化棋子为纯采集门槛，无落子特效
4. 无限复活，死亡掉落全部携带
5. 携带上限 1 棋子 + 1 道具，不做落子冷却
6. 道具品质越高，刷新位置离棋盘越远（环形分层）
7. 道具池 7 件：采集锹 / 破坏锹 / 处决剑 / 转化墨水 / 守护蜡 / 板砖雷管 / 磁铁
8. 玩法模式做成工厂 + 钩子（`gameModes/`），模式之间不互相引用；换模式只改 `config.GameMode` 一个字符串
9. 陷阱模式：地面原样不动（本图陷阱区地表是基岩，挖不动，不整平不铺伪装层——铺草皮会被挖穿打洞绕过雷区）、陷阱只存脚本数据每局重掷、先长路再定陷阱、踩中后地表方块临时变岩浆 3 秒复原回原方块、陷阱区半边长 15 格、棋盘外 2 圈是安全区
